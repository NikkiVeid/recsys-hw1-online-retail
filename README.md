# ДЗ-1: персональные рекомендации товаров

**Студент:** Вейда Никита Альбертович.

**Датасет:** [UCI Online Retail](https://archive.ics.uci.edu/dataset/352/online+retail), Chen, D. (2015), [DOI: 10.24432/C5BW33](https://doi.org/10.24432/C5BW33), CC BY 4.0.

Задача — рекомендовать десять новых для покупателя товаров на основе истории покупок. Пять моделей реализованы с нуля: ItemKNN, iALS, EASE, FM с текстовыми и ценовыми метапризнаками, iALS с собственным частотно-временным целевым сигналом. Дополнительно выполнена абляция FM без метаданных.

## Основной результат

Откройте [experiments.ipynb](experiments.ipynb): выполненные ячейки, EDA, формулы, протокол оценки, validation-поиск, финальные таблицы, графики и выводы. Численные результаты также сохраняются в [results/test_results.csv](results/test_results.csv), выбранные параметры — в [results/selected_params.json](results/selected_params.json).



После очистки: **386 326 событий, 4 334 пользователя, 3 659 товаров**. Финальная оценка: 1 440 пользователей, полный каталог из 3 607 известных товаров.

Лучший результат — **EASE** с `reg=500`. Собственный таргет iALS ухудшил NDCG@10 на 0,00646 (парный 95% bootstrap CI: −0,01153…−0,00144). Прирост FM от метаданных +0,00120, но интервал −0,00445…+0,00722 включает ноль. Это результаты заданного протокола, а не обещание прироста продаж.

Ноутбук выполнен целиком; восемь проверок формул, ранжирования и воспроизводимости пройдены.

## Воспроизведение

Проверено с Python 3.12 на CPU. Из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
# Windows: .venv\Scripts\activate
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
python run_notebook.py
```

`run_notebook.py` запускает все ячейки текущим Python и сохраняет ноутбук с результатами; глобальная регистрация Jupyter kernel не требуется. Первый запуск скачивает [архив с сайта UCI](https://archive.ics.uci.edu/static/public/352/online%2Bretail.zip), проверяет SHA-256 и читает Excel. Последующие запуски повторяют обучение, используя только кеш чтения исходных данных. Настроить каталог можно через `RECSYS_DATA_DIR`; по умолчанию это `data/`. Исходные данные в GitHub не загружаются.

SHA-256 архива:
```
f5385cbb54bbebf7196389109c6b0621faab0c304e3702548165e71c84aede8b
```

При ошибке проверки хеша удалите локальный неполный архив и скачайте его заново. Если UCI обновит источник, сначала проверьте изменения данных, затем осознанно обновите хеш. Пакеты прямых зависимостей закреплены в `requirements.txt`, полная среда воспроизведённого запуска — в `requirements-lock.txt` и `results/environment.json`. В Windows/Linux дистрибутив PyTorch и системные зависимости могут отличаться; `requirements.txt` — основной переносимый способ установки.

## Протокол

- Train до 01.09.2011; validation с 01.09.2011 до 01.11.2011; test с 01.11.2011 по конец набора.
- Основная метрика NDCG@10 выбрана до поиска. Дополнительно Recall@10 и Coverage@10.
- Общие warm-start пользователи и полный доступный до границы каталог; ранее купленные товары исключаются.
- Настройки выбираются только по validation. После фиксации — переобучение на train+validation и финальная оценка test.
- Собственный таргет: `(1 - exp(-n_ui / 2)) * exp(-age_days / tau_days)`. Confidence, rank, регуляризация и число итераций совпадают с выбранным базовым iALS.
- Метаданные, словари и цены строятся только по прошлому. Нет готовых рекомендательных библиотек, sklearn-моделей или ElasticNet.
- Seed=42; один поток CPU для BLAS и PyTorch; одинаковое разрешение ничьих для top-K.

## Ограничения

Это offline-сравнение на одном временном окне и одном seed, с ограниченным подбором. Покупки — неявная обратная связь; непокупка не равна отрицательной оценке. Наличие товара на складе неизвестно. Cold start и повторные покупки не входят в целевую метрику. В выборке есть оптовики; сезонность и изменение каталога могут влиять на результаты. Парные bootstrap-интервалы отражают вариацию пользователей внутри текущего test-окна, а не устойчивость по времени.
